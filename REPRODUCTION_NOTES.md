# Notes: DC-GRPO reproduction audit for arXiv:2606.08779

## Sources

### Paper
- URL: https://arxiv.org/pdf/2606.08779
- Version read: arXiv v2, 2026-06-09, 19 pages.
- Title: *Reformulate LLM Reinforcement Learning for Efficient Training under Black-box Discrepancy*.
- Core method: DC-GRPO / DCMDP. The rollout backend produces tokens and per-token probabilities; the training backend recomputes probabilities on the same tokens; the token-level absolute probability difference is injected into the GRPO advantage and drives a projected scalar Lagrange multiplier.
- Paper pseudocode/equation alignment: `delta = abs(pi_train - pi_inference)`, `A_DCMDP = A_GRPO - lambda * delta`, and `lambda <- clip(lambda + eta * (mean(delta) - c), lambda_min, lambda_max)`.
- Training data: BytedTsinghua-SIA/DAPO-Math-17k (paper calls it DAPO-Math-17K), math-verify rewards.
- Main setup: Qwen3-8B, BF16, FSDP2, 8 NVIDIA GPUs; 8 rollouts/prompt; response length 8192; train batch 64 prompts; PPO mini-batch 16; temperature 1.0; top-p 1.0; AdamW lr 1e-6, betas (0.9, 0.95), weight decay 0, eps 1e-15; clip high 0.24; KL loss disabled.
- Paper default DC-GRPO hyperparameters for Qwen3-8B: `lambda_init=0.1`, `lambda_lr=1.0`, `c=0.0037`; multiplier updated each training step.
- Evaluation: vLLM 0.11.0, max generation 32768, temperature 0.7, top-p 1.0; AIME24/25 and AMC23 avg@32, MATH-500/Minerva/OlympiadBench avg@4.
- Scope caveat: the paper's main numbers require 8 GPUs; one Roihu GH200 run is a reproduction/adaptation under a different hardware topology, not a claim of exact numerical replication.

## Claude Scholar review findings

### Code review
- [blocking] README scripts embed machine-specific `/mnt/ws-jfs/dsh-jfs/...` paths and a hardcoded W&B credential. The reproduction script must replace paths with Roihu scratch paths and accept `WANDB_API_KEY`/`HF_TOKEN` only from the environment.
- [blocking] The README launcher assumes `NGPUS_PER_NODE=8` and the paper's 8-GPU layout. The Roihu adaptation must explicitly use one `GH200` and reduce batch/sequence settings only if needed for a hardware smoke test; a full-data server run must not silently use a debug subset.
- [important] Generic `requirements.txt` is not a reproducible lock file. Use the fork's observed pinned versions as the target compatibility set and record the actual remote environment with `scripts/diagnose.py`.
- [important] The custom Lagrangian path is wired through `old_log_probs` (training recomputation) and `rollout_log_probs` (vLLM rollout), matching the paper's two-backend signal. With `token_prob_diff` + `absneg_0.0_none` + `abs_mean`, the applied penalty and dual update use the paper's absolute probability mismatch.
- [important] The implementation records token-level constraint statistics twice in `apply_to_advantages`; with the default `buffer_size=1` the active value is unchanged, but larger buffers can duplicate observations and should be avoided for the reproduction.
- [suggestion] Keep `buffer_size=1`, `operator_update_every_z=1`, `lambda_min=0`, `lambda_max=1`, and record lambda/discrepancy/completion markers in Slurm logs.

### Paper self-review
- Strengths: the method, equations, pseudocode, resource setup, random-seed-relevant training settings, evaluation protocol, and limitations are stated clearly enough to derive a reproduction command.
- Reproducibility gap: exact repository commit, exact dependency lock, data preprocessing checksum, and full training-step schedule are not stated in the paper. The fork README partially fills this gap but contains environment-specific paths.
- Evidence boundary: paper results use 8-GPU Qwen3-8B and 32k evaluation generations; one GH200 is suitable for a controlled reproduction run, but its metrics must be reported as an adapted run.
- Review decision: `ONE_BOUNDED_ROUND` for reproducibility documentation only. The scientific claim is supported by the paper's experiments, but an exact external rerun needs pinned environment/data provenance.
